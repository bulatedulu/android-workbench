# AI 工作台 规范

## 问题陈述

用户（开发者）在多个项目中使用终端型 AI 编码 Agent（v1 为 `pi`）进行开发。会话记录散落在 Agent 自己的本地存储里（`pi` 为 `~/.pi/agent/sessions/**/*.jsonl`）。想回顾某个项目之前的 AI 对话、在大量会话中找目标、或接着上次的工作继续时，只能逐个打开终端翻找会话文件，跨项目没有一个统一入口。工作台的价值就是解决「我的每个项目分别有哪些 AI 会话、内容是什么、怎么继续」。

## 解决方案

一个 VS Code 扩展「AI 工作台」：**项目来自当前 VS Code 工作区的文件夹**（支持 `.code-workspace` 多根工作区，可同时打开并管理多个项目，无需切换或重载窗口）。自动扫描 Agent 的本地会话存储（v1 只做 `pi`），**只展示与工作区项目文件夹匹配的会话**，按项目统一排列在侧边栏树（项目 → Agent → 会话）；单击会话在 Webview 中**快速只读加载**完整对话内容（不启动任何进程），当用户聚焦底部输入框时再恢复会话（在集成终端以 pi 继续）。会话的权威数据始终留在 Agent 自己的存储里，工作台**原地只读、从不复制内容**，写入/继续一律通过 Agent 的 CLI（见 ADR-0001）。

## 用户故事

1. 作为开发者，我想把项目文件夹加入当前工作区（支持 `.code-workspace` 多根），以便工作台自动识别并管理每个项目的 AI 会话。
2. 作为开发者，我想编辑项目的标签（名称 = 文件夹名，不可改），以便按自己的方式组织项目。
3. 作为开发者，我想从当前工作区移除一个项目文件夹，以便清理工作台（仅移除，不影响磁盘与 Agent 存储里的任何数据）。
4. 作为开发者，我想在工作台打开/刷新时自动扫描 `pi` 的会话存储，以便新会话无需手动导入就出现在工作台里。
5. 作为开发者，我想工作台只展示与当前工作区项目文件夹匹配的会话（按会话工作目录匹配到对应项目），以便视图聚焦于我的项目、不被无关会话干扰。
6. 作为开发者，我想看到每个会话的元信息（标题、创建/更新时间、使用的模型、所属 Agent），以便快速识别会话。
7. 作为开发者，我想按标题和消息文本搜索会话，以便在大量会话中定位目标。
8. 作为开发者，我想按项目、Agent、时间范围过滤会话，以便缩小浏览范围。
9. 作为开发者，我想单击一个会话快速只读加载完整对话内容（含角色与时间），以便回顾之前的思考与结论，且不启动任何进程。
10. 作为开发者，我想在会话视图聚焦底部输入框时恢复该会话（在集成终端以 pi 继续），以便想交互时才启动 pi、响应尽量快。
11. 作为开发者，我想手动触发重新扫描，以便在 Agent 产生新会话后立即看到最新状态。
12. 作为开发者，我想在 `pi` 未安装或存储目录不存在时看到明确提示而不是崩溃，以便知道环境问题。
13. 作为开发者，我想通过命令面板（`Ctrl+Shift+P`）和 Activity Bar 图标打开工作台，以便用习惯的方式进入。
14. 作为开发者，我想工作台架构上为接入其他 Agent（`omp`、`opencode`）预留 Provider 接口，以便以后统一管理多个 Agent 的会话。
15. 作为开发者，我想同时打开多个项目（多根工作区），以便同时处理多个项目而无需切换或重载窗口。
16. 作为开发者，我想在工作台添加/移除项目时动态同步当前工作区，以便项目增减即时生效、不重载窗口。
17. 作为开发者，我想工作区文件夹增删（含 VS Code 原生操作）时工作台自动刷新，以便视图始终与工作区一致。
18. 作为开发者，我想通过引导面板选择父目录、勾选其子文件夹作为项目，一键创建多根工作区并在当前窗口打开，以便快速开始多项目管理。
19. 作为开发者，我想在工作区文件已存在时直接加载，或二次确认后覆盖重建，以便反复进入同一组项目。

## 实现决策

- **技术栈**：TypeScript + VS Code Extension API；Webview 用纯 TypeScript（不引前端框架）；esbuild 打包。
- **领域层（无 VS Code 依赖，纯逻辑）**：
  - `ProjectSource`：项目来源抽象（`listProjects()` + 标签读写）；项目 = 当前工作区文件夹，名称取文件夹名，标签按路径持久化。VS Code 实现读 `workspace.workspaceFolders`（支持 `.code-workspace` 多根）。
  - `SessionModel`：会话内存模型（路径、Agent、所属项目、标题、创建/更新时间、模型）。
  - `SessionMatching`：按会话工作目录与工作区项目文件夹匹配（精确或子目录），决定会话归属；无「未归属」概念，不匹配的会话不展示。
  - `SearchService`：按标题与消息文本搜索、按项目/Agent/时间过滤。
- **项目管理（工作区驱动）**：添加项目 = `workspace.updateWorkspaceFolders` 动态加入文件夹；移除项目 = 从工作区移除文件夹（均**不重载窗口**）；监听 `onDidChangeWorkspaceFolders` 自动刷新树；名称 = 文件夹名（不提供重命名），标签按路径存 globalStorage JSON。
- **多根工作区引导面板（Webview，编辑器区居中）**：选父目录 → 列出子文件夹可勾选 → 工作区文件名默认 `<父目录名>.code-workspace`（可输入修改）→ 确认后生成文件并在当前窗口打开（`vscode.openFolder`）；目标已存在则直接加载，「覆盖重建」需二次确认。纯逻辑（文件名、JSON 生成、子目录列举、HTML 构建）抽为可测函数；面板分区结构，为后续默认 Agent / key 配置预留。入口：命令 + 视图标题栏按钮（不自动弹出）。
- **Provider 接口（Agent 适配层）**：
  - `AgentProvider` 接口：`discoverStore()`、`scanSessions()`、`readSessionContent()`、`resumeSession()`。
  - `PiProvider`（v1 唯一实现）：按 `pi` 的存储约定扫描 `~/.pi/agent/sessions/`，解析 JSONL（含版本头，容忍版本迁移），通过 `pi --resume <file>` 继续会话。
- **pi 集成方式（v1 定案，刻意不用 SDK）**：读取走**直接解析 JSONL**（格式有官方文档 + 版本头，稳定可容忍迁移）；继续走 **CLI** `pi --resume <file>`（与用户安装的 pi 版本解耦，不把整个 agent 作为依赖打进扩展）。二期做聊天 UI 需要编程式驱动时，再评估 SDK 或 `--mode rpc`。
- **UI 壳层（保持薄，只做转发）**：Activity Bar 图标 + Tree View（项目 → Agent → 会话）；Webview 会话视图（只读内容 + 底部输入框，聚焦输入框触发恢复会话）；命令（打开工作台、添加项目、刷新扫描）。
- **数据流**：打开/刷新时按需扫描 `pi` 存储（仅保留与工作区项目文件夹匹配的会话）→ 构建内存会话模型 → 渲染树；单击会话 → 读取内容 → Webview 快速只读展示；聚焦底部输入框 → 触发在 `pi` 中恢复（CLI 启动，集成终端）。
- **与 ADR-0001 一致**：工作台绝不修改 Agent 存储文件；v1 无持久化索引，globalStorage 仅存项目注册表。
- **消息协议**：扩展宿主与 Webview 之间用标准 `postMessage`。

## 测试决策

- **好测试的标准**：只测外部行为，不测实现细节；用 fixture 数据驱动，不依赖真实用户目录。
- **接缝 1（领域层）**：用假 `ProjectSource`（临时目录）测试 `WorkbenchService`、`SessionModel`、`SessionMatching`、`SearchService`；标签存储用临时文件测试。纯逻辑、无 VS Code API，速度快。
- **接缝 2（Provider）**：`PiProvider` 用临时目录里真实 `pi` 格式的 JSONL（含版本头）测试扫描、读取、版本容忍、路径匹配；`resumeSession` 通过注入的命令执行器（mock CLI）验证调用参数；「聚焦输入框 → 触发恢复」的触发逻辑同样以注入命令执行器测试。
- **UI 壳层**：保持薄，逻辑下沉到领域层；命令与树渲染的集成测试为可选（扩展宿主），以手工验证兜底。
- **测试框架**：Vitest（Node 环境）；VS Code API 一律通过接口/依赖注入隔离，不在单元测试中直接触碰。

## 范围外

- 工作台自带聊天 UI（二期，通过驱动 Agent SDK 实现，非自带模型）。
- 「未归属会话」的展示与手动绑定（v1 只展示与工作区项目文件夹匹配的会话）。
- 「点击项目切换工作区」（改为多根工作区同时打开，不切换不重载）。
- 在 Webview 内直接输入对话（v1 聚焦输入框为交接到集成终端；webview 内对话为二期，经 SDK/RPC）。
- `omp`、`opencode` 的 Provider（二期，按同一接口接入）。
- 会话的标签/归档/统计、导入导出。
- 团队同步/云共享（预留扩展点）。
- 修改 `pi` 的存储格式或直接写 Agent 存储。
- 跨 Agent 的持久化全局搜索索引（会话量大到需要时再做）。
