# 0001: In-place read of agent session stores

Sessions are authoritative in each Agent's own store — `pi`/`omp` write JSONL files, `opencode` writes SQLite (`opencode.db`) — and the workbench never copies that content. It scans the Agent store on demand, building an in-memory session model (path, agent, project, title, time, model), and reads session content from the store only when needed — opening a session or searching message text. No persistent index in v1 — it is deferred until session volume or cross-agent search demands it. We chose in-place read over full import/mirroring (stale copies, drift, duplicate storage). Writing to sessions goes through the Agent's own CLI/SDK (`pi --resume`, `omp --resume`, `opencode session list`) — the workbench never edits store files directly.
